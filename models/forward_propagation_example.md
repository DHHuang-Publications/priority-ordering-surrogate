# PermutationTransformer Forward Propagation 完整範例

> **設定**：K=3 (3 個 source-terminal pairs)、d_model=4、nhead=2、batch_size=1
> 為方便手算，所有權重都用簡單數值，且僅展示 1 層 encoder。

---

## Step 0：定義輸入資料

```
perm   = [2, 0, 1]      # 排列（優先順序）
demand = [10, 30, 5]     # 需求向量（按 pair index 排列）
```

**白話解讀**：

| 位置 (position) | 優先權 | 放的是哪個 pair | 該 pair 的需求 |
|:---:|:---:|:---:|:---:|
| pos 0 | 最高 | pair 2 | demand[2] = 5 |
| pos 1 | 中等 | pair 0 | demand[0] = 10 |
| pos 2 | 最低 | pair 1 | demand[1] = 30 |

> 📝 **註解**：pair 1 需求最大 (30)，卻被排在最低優先位置。
> 這意味著 pair 1 只能拿到前兩個 pair 用剩的容量，可能導致它無法達標。
> 模型的任務就是學習：這種排列+需求組合會產出多高的 joint reliability。

---

## Step 1：Pair Embedding — 查表得到「身份向量」

### 1.1 Embedding 查找表

`self.pair_embedding = nn.Embedding(K=3, d_model=4)`

這是一張可學習的查找表，每個 pair index 對應一個 4 維向量：

```
E_pair = [
  pair 0: [ 0.2, -0.5,  0.8,  0.1],   # pair 0 的身份向量
  pair 1: [ 0.9,  0.1, -0.3,  0.6],   # pair 1 的身份向量
  pair 2: [-0.4,  0.7,  0.6, -0.2],   # pair 2 的身份向量
]
```

> 📝 **註解**：這些向量在訓練前是隨機初始化的，訓練後會學到有意義的表示。
> 例如共享很多邊的 pair，它們的 embedding 可能會比較接近。

### 1.2 查表過程

程式碼：`pair_emb = self.pair_embedding(perm)`

perm = [2, 0, 1]，所以：

```
pos 0 → 查 E_pair[2] = [-0.4,  0.7,  0.6, -0.2]
pos 1 → 查 E_pair[0] = [ 0.2, -0.5,  0.8,  0.1]
pos 2 → 查 E_pair[1] = [ 0.9,  0.1, -0.3,  0.6]
```

### 1.3 結果

```
pair_emb = [
  pos 0: [-0.4,  0.7,  0.6, -0.2],   ← pair 2 的身份
  pos 1: [ 0.2, -0.5,  0.8,  0.1],   ← pair 0 的身份
  pos 2: [ 0.9,  0.1, -0.3,  0.6],   ← pair 1 的身份
]
shape: (1, 3, 4)  即 (batch, K, d_model)
```

> 📝 **註解**：注意 pair_emb 的排列順序跟 perm 一致（不是按 pair 0,1,2 的順序）。
> 這樣每個位置的 token 就「知道自己代表哪個 pair」。

---

## Step 2：Positional Embedding — 編碼「排第幾」

### 2.1 Positional Embedding 查找表

`self.pos_embedding = nn.Embedding(K=3, d_model=4)`

```
E_pos = [
  pos 0: [ 0.5,  0.3, -0.1,  0.4],   # 最高優先權的位置編碼
  pos 1: [-0.2,  0.6,  0.2, -0.3],   # 中等優先權
  pos 2: [ 0.1, -0.4,  0.7,  0.0],   # 最低優先權
]
```

### 2.2 查表過程

程式碼：
```python
positions = torch.arange(3)          # [0, 1, 2]
pos_emb = self.pos_embedding(positions)  # 直接按 0,1,2 查表
```

```
pos 0 → E_pos[0] = [ 0.5,  0.3, -0.1,  0.4]
pos 1 → E_pos[1] = [-0.2,  0.6,  0.2, -0.3]
pos 2 → E_pos[2] = [ 0.1, -0.4,  0.7,  0.0]
```

### 2.3 結果

```
pos_emb = [
  pos 0: [ 0.5,  0.3, -0.1,  0.4],   ← "我排第 0（最優先）"
  pos 1: [-0.2,  0.6,  0.2, -0.3],   ← "我排第 1"
  pos 2: [ 0.1, -0.4,  0.7,  0.0],   ← "我排第 2（最後）"
]
shape: (1, 3, 4)
```

> 📝 **註解**：Positional Embedding 跟排列 perm 無關，它只編碼「位置本身」。
> 不管哪個 pair 坐在 pos 0，pos 0 的位置向量永遠是 [0.5, 0.3, -0.1, 0.4]。
> 這告訴模型「在這個位置的 pair 享有最高優先權，能拿到最多容量」。

---

## Step 3：Demand Projection — 把需求量映射到向量空間

### 3.1 Gather 操作：按排列順序重新排列 demand

程式碼：`demand_at_pos = torch.gather(demand, 1, perm)`

```
demand     = [10, 30, 5]     # 原始：pair 0=10, pair 1=30, pair 2=5
perm       = [2,  0,  1]     # 排列

demand_at_pos[0] = demand[perm[0]] = demand[2] = 5    ← pos 0 放的是 pair 2
demand_at_pos[1] = demand[perm[1]] = demand[0] = 10   ← pos 1 放的是 pair 0
demand_at_pos[2] = demand[perm[2]] = demand[1] = 30   ← pos 2 放的是 pair 1

demand_at_pos = [5, 10, 30]
```

> 📝 **註解**：gather 確保每個位置拿到的 demand 是「坐在那個位置的 pair」的需求值，
> 而不是按 pair index 順序排的值。這一步至關重要，否則 demand 和 pair embedding 會對不上。

### 3.2 Reshape 成 (batch, K, 1)

```
demand_at_pos = [[5], [10], [30]]    # shape: (1, 3, 1)
```

### 3.3 Linear 投射

`self.demand_proj = nn.Linear(1, 4)`

假設學到的參數：
```
W_d = [[0.10],      # shape: (4, 1)  — 4 個輸出維度，1 個輸入
       [-0.20],
       [0.30],
       [0.05]]
b_d = [0.00, 0.10, -0.10, 0.00]    # bias, shape: (4,)
```

投射公式：`demand_emb[pos] = demand_at_pos[pos] × W_d^T + b_d`

逐一計算：

```
pos 0 (demand = 5):
  5 × [0.10, -0.20, 0.30, 0.05] + [0.00, 0.10, -0.10, 0.00]
= [0.50, -1.00, 1.50, 0.25] + [0.00, 0.10, -0.10, 0.00]
= [0.50, -0.90, 1.40, 0.25]

pos 1 (demand = 10):
  10 × [0.10, -0.20, 0.30, 0.05] + [0.00, 0.10, -0.10, 0.00]
= [1.00, -2.00, 3.00, 0.50] + [0.00, 0.10, -0.10, 0.00]
= [1.00, -1.90, 2.90, 0.50]

pos 2 (demand = 30):
  30 × [0.10, -0.20, 0.30, 0.05] + [0.00, 0.10, -0.10, 0.00]
= [3.00, -6.00, 9.00, 1.50] + [0.00, 0.10, -0.10, 0.00]
= [3.00, -5.90, 8.90, 1.50]
```

### 3.4 結果

```
demand_emb = [
  pos 0: [ 0.50, -0.90,  1.40,  0.25],   ← demand=5（小需求，向量幅度小）
  pos 1: [ 1.00, -1.90,  2.90,  0.50],   ← demand=10（中需求）
  pos 2: [ 3.00, -5.90,  8.90,  1.50],   ← demand=30（大需求，向量幅度大）
]
shape: (1, 3, 4)
```

> 📝 **註解**：demand 越大，投射出來的向量各分量的絕對值越大。
> 這讓模型能區分「高需求 pair」和「低需求 pair」。
> pair 1 的 demand=30 產出的向量幅度是 pair 2 (demand=5) 的 6 倍！

---

## Step 4：Additive Fusion — 三路嵌入逐元素相加

程式碼：`x = pair_emb + pos_emb + demand_emb`

### 4.1 逐位置計算

**Position 0**（pair 2, 最高優先, demand=5）：

```
pair_emb[0]   = [-0.40,  0.70,  0.60, -0.20]   ← "我是 pair 2"
pos_emb[0]    = [ 0.50,  0.30, -0.10,  0.40]   ← "我排最前面"
demand_emb[0] = [ 0.50, -0.90,  1.40,  0.25]   ← "我的需求是 5"
──────────────────────────────────────────────
sum           = [ 0.60,  0.10,  1.90,  0.45]
```

計算過程（逐維度）：
```
dim 0: -0.40 + 0.50 + 0.50 = 0.60
dim 1:  0.70 + 0.30 + (-0.90) = 0.10
dim 2:  0.60 + (-0.10) + 1.40 = 1.90
dim 3: -0.20 + 0.40 + 0.25 = 0.45
```

**Position 1**（pair 0, 中等優先, demand=10）：

```
pair_emb[1]   = [ 0.20, -0.50,  0.80,  0.10]   ← "我是 pair 0"
pos_emb[1]    = [-0.20,  0.60,  0.20, -0.30]   ← "我排第二"
demand_emb[1] = [ 1.00, -1.90,  2.90,  0.50]   ← "我的需求是 10"
──────────────────────────────────────────────
sum           = [ 1.00, -1.80,  3.90,  0.30]
```

計算過程：
```
dim 0:  0.20 + (-0.20) + 1.00 = 1.00
dim 1: -0.50 + 0.60 + (-1.90) = -1.80
dim 2:  0.80 + 0.20 + 2.90 = 3.90
dim 3:  0.10 + (-0.30) + 0.50 = 0.30
```

**Position 2**（pair 1, 最低優先, demand=30）：

```
pair_emb[2]   = [ 0.90,  0.10, -0.30,  0.60]   ← "我是 pair 1"
pos_emb[2]    = [ 0.10, -0.40,  0.70,  0.00]   ← "我排最後"
demand_emb[2] = [ 3.00, -5.90,  8.90,  1.50]   ← "我的需求是 30"
──────────────────────────────────────────────
sum           = [ 4.00, -6.20,  9.30,  2.10]
```

計算過程：
```
dim 0:  0.90 + 0.10 + 3.00 = 4.00
dim 1:  0.10 + (-0.40) + (-5.90) = -6.20
dim 2: -0.30 + 0.70 + 8.90 = 9.30
dim 3:  0.60 + 0.00 + 1.50 = 2.10
```

### 4.2 融合結果 Z⁰（Transformer 的輸入序列）

```
Z⁰ = [
  z₀ = [ 0.60,  0.10,  1.90,  0.45],   ← token 0: pair 2 在 pos 0, d=5
  z₁ = [ 1.00, -1.80,  3.90,  0.30],   ← token 1: pair 0 在 pos 1, d=10
  z₂ = [ 4.00, -6.20,  9.30,  2.10],   ← token 2: pair 1 在 pos 2, d=30
]
shape: (1, 3, 4)  即 (batch, K, d_model)
```

> 📝 **註解**：每個 token 現在同時攜帶三種資訊：
> - 身份：「我是哪個 pair」（pair embedding 貢獻）
> - 位置：「我排在第幾位」（positional embedding 貢獻）
> - 需求：「我需要多少容量」（demand projection 貢獻）
>
> 注意 z₂ 的幅度明顯大於 z₀ 和 z₁，因為 pair 1 的 demand=30 遠大於其他 pair。

---

## Step 5：Transformer Encoder — Multi-Head Self-Attention

### 5.0 架構概覽

nhead=2, d_model=4, 所以 d_k = d_model / nhead = 4 / 2 = 2

每個 head 負責 2 個維度。

### 5.1 Q, K, V 投影矩陣

每個 head 有自己的 W_Q, W_K, W_V，shape 都是 (d_model, d_k) = (4, 2)。

```
Head 0:
  W_Q⁰ = [[ 0.3, -0.1],    W_K⁰ = [[ 0.2,  0.4],    W_V⁰ = [[ 0.1, -0.2],
           [ 0.2,  0.5],             [-0.3,  0.1],             [ 0.3,  0.4],
           [-0.1,  0.3],             [ 0.5, -0.2],             [-0.1,  0.2],
           [ 0.4, -0.2]]            [ 0.1,  0.3]]            [ 0.2,  0.1]]

Head 1:
  W_Q¹ = [[-0.2,  0.4],    W_K¹ = [[ 0.1, -0.3],    W_V¹ = [[ 0.2,  0.3],
           [ 0.3, -0.1],             [ 0.4,  0.2],             [-0.1,  0.1],
           [ 0.1,  0.2],             [-0.2,  0.5],             [ 0.4, -0.2],
           [-0.3,  0.1]]            [ 0.3, -0.1]]            [ 0.1,  0.5]]
```

### 5.2 計算 Head 0 的 Q, K, V

**Q⁰ = Z⁰ × W_Q⁰**（shape: (3,4) × (4,2) = (3,2)）

```
Q⁰[0] = z₀ × W_Q⁰
       = [0.60, 0.10, 1.90, 0.45] × W_Q⁰
       dim 0: 0.60×0.3 + 0.10×0.2 + 1.90×(-0.1) + 0.45×0.4
            = 0.18 + 0.02 - 0.19 + 0.18 = 0.19
       dim 1: 0.60×(-0.1) + 0.10×0.5 + 1.90×0.3 + 0.45×(-0.2)
            = -0.06 + 0.05 + 0.57 - 0.09 = 0.47
       → Q⁰[0] = [0.19, 0.47]

Q⁰[1] = z₁ × W_Q⁰
       = [1.00, -1.80, 3.90, 0.30] × W_Q⁰
       dim 0: 1.00×0.3 + (-1.80)×0.2 + 3.90×(-0.1) + 0.30×0.4
            = 0.30 - 0.36 - 0.39 + 0.12 = -0.33
       dim 1: 1.00×(-0.1) + (-1.80)×0.5 + 3.90×0.3 + 0.30×(-0.2)
            = -0.10 - 0.90 + 1.17 - 0.06 = 0.11
       → Q⁰[1] = [-0.33, 0.11]

Q⁰[2] = z₂ × W_Q⁰
       = [4.00, -6.20, 9.30, 2.10] × W_Q⁰
       dim 0: 4.00×0.3 + (-6.20)×0.2 + 9.30×(-0.1) + 2.10×0.4
            = 1.20 - 1.24 - 0.93 + 0.84 = -0.13
       dim 1: 4.00×(-0.1) + (-6.20)×0.5 + 9.30×0.3 + 2.10×(-0.2)
            = -0.40 - 3.10 + 2.79 - 0.42 = -1.13
       → Q⁰[2] = [-0.13, -1.13]
```

**K⁰ = Z⁰ × W_K⁰**

```
K⁰[0] = z₀ × W_K⁰ = [0.60, 0.10, 1.90, 0.45] × W_K⁰
       dim 0: 0.60×0.2 + 0.10×(-0.3) + 1.90×0.5 + 0.45×0.1
            = 0.12 - 0.03 + 0.95 + 0.045 = 1.085
       dim 1: 0.60×0.4 + 0.10×0.1 + 1.90×(-0.2) + 0.45×0.3
            = 0.24 + 0.01 - 0.38 + 0.135 = 0.005
       → K⁰[0] = [1.085, 0.005]

K⁰[1] = z₁ × W_K⁰ = [1.00, -1.80, 3.90, 0.30] × W_K⁰
       dim 0: 1.00×0.2 + (-1.80)×(-0.3) + 3.90×0.5 + 0.30×0.1
            = 0.20 + 0.54 + 1.95 + 0.03 = 2.72
       dim 1: 1.00×0.4 + (-1.80)×0.1 + 3.90×(-0.2) + 0.30×0.3
            = 0.40 - 0.18 - 0.78 + 0.09 = -0.47
       → K⁰[1] = [2.72, -0.47]

K⁰[2] = z₂ × W_K⁰ = [4.00, -6.20, 9.30, 2.10] × W_K⁰
       dim 0: 4.00×0.2 + (-6.20)×(-0.3) + 9.30×0.5 + 2.10×0.1
            = 0.80 + 1.86 + 4.65 + 0.21 = 7.52
       dim 1: 4.00×0.4 + (-6.20)×0.1 + 9.30×(-0.2) + 2.10×0.3
            = 1.60 - 0.62 - 1.86 + 0.63 = -0.25
       → K⁰[2] = [7.52, -0.25]
```

**V⁰ = Z⁰ × W_V⁰**

```
V⁰[0] = z₀ × W_V⁰ = [0.60, 0.10, 1.90, 0.45] × W_V⁰
       dim 0: 0.60×0.1 + 0.10×0.3 + 1.90×(-0.1) + 0.45×0.2
            = 0.06 + 0.03 - 0.19 + 0.09 = -0.01
       dim 1: 0.60×(-0.2) + 0.10×0.4 + 1.90×0.2 + 0.45×0.1
            = -0.12 + 0.04 + 0.38 + 0.045 = 0.345
       → V⁰[0] = [-0.01, 0.345]

V⁰[1] = z₁ × W_V⁰ = [1.00, -1.80, 3.90, 0.30] × W_V⁰
       dim 0: 1.00×0.1 + (-1.80)×0.3 + 3.90×(-0.1) + 0.30×0.2
            = 0.10 - 0.54 - 0.39 + 0.06 = -0.77
       dim 1: 1.00×(-0.2) + (-1.80)×0.4 + 3.90×0.2 + 0.30×0.1
            = -0.20 - 0.72 + 0.78 + 0.03 = -0.11
       → V⁰[1] = [-0.77, -0.11]

V⁰[2] = z₂ × W_V⁰ = [4.00, -6.20, 9.30, 2.10] × W_V⁰
       dim 0: 4.00×0.1 + (-6.20)×0.3 + 9.30×(-0.1) + 2.10×0.2
            = 0.40 - 1.86 - 0.93 + 0.42 = -1.97
       dim 1: 4.00×(-0.2) + (-6.20)×0.4 + 9.30×0.2 + 2.10×0.1
            = -0.80 - 2.48 + 1.86 + 0.21 = -1.21
       → V⁰[2] = [-1.97, -1.21]
```

### 5.3 計算 Head 0 的 Attention Scores

**score = Q⁰ × (K⁰)ᵀ / √d_k**，其中 √d_k = √2 ≈ 1.414

```
Q⁰ × (K⁰)ᵀ:                         (3,2) × (2,3) = (3,3)

              K⁰[0]=[1.085, 0.005]  K⁰[1]=[2.72, -0.47]  K⁰[2]=[7.52, -0.25]

Q⁰[0]=[0.19, 0.47]:
  score(0,0) = 0.19×1.085 + 0.47×0.005 = 0.206 + 0.002 = 0.209
  score(0,1) = 0.19×2.72  + 0.47×(-0.47) = 0.517 - 0.221 = 0.296
  score(0,2) = 0.19×7.52  + 0.47×(-0.25) = 1.429 - 0.118 = 1.311

Q⁰[1]=[-0.33, 0.11]:
  score(1,0) = -0.33×1.085 + 0.11×0.005 = -0.358 + 0.001 = -0.357
  score(1,1) = -0.33×2.72  + 0.11×(-0.47) = -0.898 - 0.052 = -0.949
  score(1,2) = -0.33×7.52  + 0.11×(-0.25) = -2.482 - 0.028 = -2.509

Q⁰[2]=[-0.13, -1.13]:
  score(2,0) = -0.13×1.085 + (-1.13)×0.005 = -0.141 - 0.006 = -0.147
  score(2,1) = -0.13×2.72  + (-1.13)×(-0.47) = -0.354 + 0.531 = 0.178
  score(2,2) = -0.13×7.52  + (-1.13)×(-0.25) = -0.978 + 0.283 = -0.695
```

**除以 √d_k = 1.414：**

```
scaled_score = [
  [ 0.148,  0.209,  0.927],   ← query = pos 0
  [-0.252, -0.671, -1.774],   ← query = pos 1
  [-0.104,  0.126, -0.492],   ← query = pos 2
]
```

### 5.4 Softmax — 得到注意力權重

對每一行做 softmax：`softmax(x_i) = exp(x_i) / Σ exp(x_j)`

**Row 0**（pos 0 作為 query）：
```
exp(0.148) = 1.160,  exp(0.209) = 1.233,  exp(0.927) = 2.527
sum = 1.160 + 1.233 + 2.527 = 4.920

α(0,0) = 1.160 / 4.920 = 0.236
α(0,1) = 1.233 / 4.920 = 0.251
α(0,2) = 2.527 / 4.920 = 0.514   ← pos 0 最關注 pos 2 (pair 1, demand=30)
```

**Row 1**（pos 1 作為 query）：
```
exp(-0.252) = 0.777,  exp(-0.671) = 0.511,  exp(-1.774) = 0.170
sum = 0.777 + 0.511 + 0.170 = 1.458

α(1,0) = 0.777 / 1.458 = 0.533   ← pos 1 最關注 pos 0 (pair 2, 最高優先)
α(1,1) = 0.511 / 1.458 = 0.350
α(1,2) = 0.170 / 1.458 = 0.117
```

**Row 2**（pos 2 作為 query）：
```
exp(-0.104) = 0.901,  exp(0.126) = 1.134,  exp(-0.492) = 0.611
sum = 0.901 + 1.134 + 0.611 = 2.646

α(2,0) = 0.901 / 2.646 = 0.340
α(2,1) = 1.134 / 2.646 = 0.429   ← pos 2 最關注 pos 1 (pair 0, 中等優先)
α(2,2) = 0.611 / 2.646 = 0.231
```

### 5.5 注意力權重矩陣（Head 0）

```
Attention⁰ = [
         key→  pos 0    pos 1    pos 2
  pos 0:     [ 0.236,   0.251,   0.514 ]
  pos 1:     [ 0.533,   0.350,   0.117 ]
  pos 2:     [ 0.340,   0.429,   0.231 ]
]
```

> 📝 **註解**：如何解讀這個矩陣？
>
> - pos 0（pair 2, demand=5, 最優先）最關注 pos 2（pair 1, demand=30），
>   權重 0.514。直覺：pair 2 雖然排最前面拿容量，但它在「看」pair 1 
>   是否會造成整體系統壓力（因為 pair 1 需求很大）。
>
> - pos 1（pair 0, demand=10）最關注 pos 0（pair 2），權重 0.533。
>   直覺：pair 0 在看「排在我前面的 pair 2 會消耗多少容量」。
>
> - pos 2（pair 1, demand=30, 最後）最關注 pos 1（pair 0），權重 0.429。
>   直覺：pair 1 排最後，它需要知道前面的 pair 們用掉多少容量。
>
> 這就是 self-attention 如何自動學習「容量競爭」的機制！

### 5.6 Head 0 的加權輸出

**head⁰ = Attention⁰ × V⁰**

```
head⁰[0] = 0.236×V⁰[0] + 0.251×V⁰[1] + 0.514×V⁰[2]
         = 0.236×[-0.01, 0.345] + 0.251×[-0.77, -0.11] + 0.514×[-1.97, -1.21]
         
  dim 0: 0.236×(-0.01) + 0.251×(-0.77) + 0.514×(-1.97)
       = -0.002 - 0.193 - 1.013 = -1.208
  dim 1: 0.236×(0.345) + 0.251×(-0.11) + 0.514×(-1.21)
       = 0.081 - 0.028 - 0.622 = -0.569
  → head⁰[0] = [-1.208, -0.569]

head⁰[1] = 0.533×V⁰[0] + 0.350×V⁰[1] + 0.117×V⁰[2]
  dim 0: 0.533×(-0.01) + 0.350×(-0.77) + 0.117×(-1.97)
       = -0.005 - 0.270 - 0.230 = -0.505
  dim 1: 0.533×0.345 + 0.350×(-0.11) + 0.117×(-1.21)
       = 0.184 - 0.039 - 0.142 = 0.003
  → head⁰[1] = [-0.505, 0.003]

head⁰[2] = 0.340×V⁰[0] + 0.429×V⁰[1] + 0.231×V⁰[2]
  dim 0: 0.340×(-0.01) + 0.429×(-0.77) + 0.231×(-1.97)
       = -0.003 - 0.330 - 0.455 = -0.789
  dim 1: 0.340×0.345 + 0.429×(-0.11) + 0.231×(-1.21)
       = 0.117 - 0.047 - 0.280 = -0.210
  → head⁰[2] = [-0.789, -0.210]
```

> 📝 **註解**：Head 1 的計算方式完全相同，只是使用 W_Q¹, W_K¹, W_V¹ 不同的權重。
> 多頭的設計讓不同 head 可以學習不同類型的交互模式。
> 例如 Head 0 可能學到「需求量」的競爭，Head 1 可能學到「路徑重疊」的影響。

### 5.7 Multi-Head Concatenation + Output Projection

假設 Head 1 算出：
```
head¹ = [
  [ 0.42, -0.15],
  [-0.28,  0.63],
  [ 0.11, -0.37],
]
```

**Concat**（把 head⁰ 和 head¹ 拼接回 d_model=4 維）：
```
MHSA_raw = [
  [-1.208, -0.569,  0.42, -0.15],   ← pos 0
  [-0.505,  0.003, -0.28,  0.63],   ← pos 1
  [-0.789, -0.210,  0.11, -0.37],   ← pos 2
]
shape: (3, 4)
```

**Output Projection**：MHSA = MHSA_raw × W_O

```
W_O shape: (4, 4)  — 把 concat 後的結果投影回 d_model 維
```

假設乘完 W_O 後得到：
```
MHSA = [
  [-0.85,  0.32,  0.14, -0.28],
  [-0.21,  0.47, -0.35,  0.19],
  [-0.62, -0.15,  0.08, -0.41],
]
```

### 5.8 Residual Connection + Layer Norm

```
a = LayerNorm(Z⁰ + MHSA)
```

**Residual**（跳接）：
```
Z⁰ + MHSA:
  pos 0: [ 0.60+(-0.85),  0.10+0.32,  1.90+0.14,  0.45+(-0.28)] = [-0.25,  0.42,  2.04,  0.17]
  pos 1: [ 1.00+(-0.21), -1.80+0.47,  3.90+(-0.35), 0.30+0.19]  = [ 0.79, -1.33,  3.55,  0.49]
  pos 2: [ 4.00+(-0.62), -6.20+(-0.15), 9.30+0.08, 2.10+(-0.41)]= [ 3.38, -6.35,  9.38,  1.69]
```

> 📝 **註解**：Residual connection 把原始輸入加回來，避免深層網路中資訊丟失。
> 即使 self-attention 學壞了，至少原始 token 資訊還在。

**Layer Norm**（對每個 token 獨立正規化）：

以 pos 0 = [-0.25, 0.42, 2.04, 0.17] 為例：
```
mean = (-0.25 + 0.42 + 2.04 + 0.17) / 4 = 2.38 / 4 = 0.595
var  = [(-0.25-0.595)² + (0.42-0.595)² + (2.04-0.595)² + (0.17-0.595)²] / 4
     = [0.713 + 0.031 + 2.088 + 0.181] / 4 = 3.013 / 4 = 0.753
std  = √0.753 = 0.868

normalized:
  dim 0: (-0.25 - 0.595) / 0.868 = -0.973
  dim 1: (0.42 - 0.595) / 0.868  = -0.202
  dim 2: (2.04 - 0.595) / 0.868  =  1.665
  dim 3: (0.17 - 0.595) / 0.868  = -0.490
```

> 📝 **註解**：LayerNorm 讓每個 token 的各維度重新分配到均值=0、方差=1 附近，
> 穩定訓練過程，避免某些維度的數值暴漲或消失。
> 實際上 LayerNorm 還有可學習的 γ (scale) 和 β (shift) 參數，這裡省略。

### 5.9 Feed-Forward Network (FFN)

```
FFN(x) = GELU(x × W₁ + b₁) × W₂ + b₂
```

其中 W₁ ∈ R^{4×8}（d_model → dim_ff=8），W₂ ∈ R^{8×4}（dim_ff → d_model）

> 📝 **註解**：FFN 先「膨脹」到 dim_ff=8 維（讓模型有更大的表達空間），
> 經過 GELU 非線性激活後再「壓縮」回 d_model=4 維。
> 為簡潔，此處省略 FFN 的逐元素計算，概念同普通 MLP。

### 5.10 第二次 Residual + LayerNorm

```
Z¹ = LayerNorm(a + FFN(a))
```

假設經過完整 1 層 encoder 後：
```
Z¹ = [
  pos 0: [ 0.82, -0.35,  1.24,  0.61],
  pos 1: [ 1.15, -1.42,  2.78,  0.53],
  pos 2: [ 2.91, -4.10,  6.55,  1.73],
]
shape: (1, 3, 4)
```

> 📝 **註解**：實際模型有 L=3 層 encoder，每層都重複上述的
> self-attention → residual → LN → FFN → residual → LN 流程。
> 更深的層可以捕捉更高階的 pair 交互關係。

## Step 6：Global Average Pooling — 壓縮序列維度

程式碼：`x = x.mean(dim=1)`

```
r = mean(Z_out, dim=1)    # 沿著 K=3 個位置取平均

r = [
  (0.82 + 1.15 + 2.91) / 3,     = 4.88 / 3 = 1.627
  (-0.35 + (-1.42) + (-4.10)) / 3, = -5.87 / 3 = -1.957
  (1.24 + 2.78 + 6.55) / 3,     = 10.57 / 3 = 3.523
  (0.61 + 0.53 + 1.73) / 3,     = 2.87 / 3 = 0.957
]

r = [1.627, -1.957, 3.523, 0.957]
shape: (1, 4)  即 (batch, d_model)
```

> 📝 **註解**：為什麼用 mean 而不是取特定位置（如 [CLS] token）？
> 因為 joint reliability 取決於「所有 pair 是否同時達標」，
> 任何一個位置的 pair 失敗都會導致 R_joint = 0。
> Mean pooling 讓所有位置平等貢獻，符合 joint reliability 的語義：
> 它不是「某一個 pair 的表現」，而是「整體排列的綜合效果」。

## Step 7：Regression Head — 輸出預測值

### 7.1 第一層 Linear + GELU

```python
self.regression_head = nn.Sequential(
    nn.Linear(d_model, d_model),   # Linear: 4 → 4
    nn.GELU(),
    nn.Dropout(dropout),
    nn.Linear(d_model, 1),         # Linear: 4 → 1
)
```

假設第一層的權重：
```
W_hid = [[ 0.30,  0.10, -0.20,  0.15],
         [-0.10,  0.25,  0.40, -0.30],
         [ 0.20, -0.15,  0.35,  0.10],
         [ 0.05,  0.30, -0.10,  0.20]]

b_hid = [0.10, -0.05, 0.08, 0.02]
```

**h = W_hid × r + b_hid：**

```
h[0] = 0.30×1.627 + 0.10×(-1.957) + (-0.20)×3.523 + 0.15×0.957 + 0.10
     = 0.488 - 0.196 - 0.705 + 0.144 + 0.10
     = -0.169

h[1] = -0.10×1.627 + 0.25×(-1.957) + 0.40×3.523 + (-0.30)×0.957 + (-0.05)
     = -0.163 - 0.489 + 1.409 - 0.287 - 0.05
     = 0.420

h[2] = 0.20×1.627 + (-0.15)×(-1.957) + 0.35×3.523 + 0.10×0.957 + 0.08
     = 0.325 + 0.294 + 1.233 + 0.096 + 0.08
     = 2.028

h[3] = 0.05×1.627 + 0.30×(-1.957) + (-0.10)×3.523 + 0.20×0.957 + 0.02
     = 0.081 - 0.587 - 0.352 + 0.191 + 0.02
     = -0.647

h_pre_activation = [-0.169, 0.420, 2.028, -0.647]
```

**GELU 激活：**

```
GELU(x) ≈ x × Φ(x)，其中 Φ 是標準常態分佈的 CDF

GELU(-0.169) ≈ -0.169 × Φ(-0.169) ≈ -0.169 × 0.433 = -0.073
GELU(0.420)  ≈  0.420 × Φ(0.420)  ≈  0.420 × 0.663 =  0.278
GELU(2.028)  ≈  2.028 × Φ(2.028)  ≈  2.028 × 0.979 =  1.985
GELU(-0.647) ≈ -0.647 × Φ(-0.647) ≈ -0.647 × 0.259 = -0.167

h_activated = [-0.073, 0.278, 1.985, -0.167]
```

> 📝 **註解**：GELU 和 ReLU 類似，會抑制負值，但不像 ReLU 那樣硬截斷為 0。
> GELU 允許小幅度的負值通過（如 -0.073 和 -0.167），讓梯度流更平滑。

### 7.2 Dropout（推理時不啟用）

> 📝 **註解**：Dropout 在 training 時隨機把一些神經元設為 0（正則化，防止過擬合），
> 在 inference / eval 模式下是 no-op（什麼都不做），所以這裡跳過。

### 7.3 第二層 Linear — 最終輸出

假設：
```
W_out = [0.30, 0.15, 0.25, -0.10]    # shape: (1, 4)
b_out = 0.05
```

```
R_hat = W_out × h_activated + b_out
      = 0.30×(-0.073) + 0.15×0.278 + 0.25×1.985 + (-0.10)×(-0.167) + 0.05
      = -0.022 + 0.042 + 0.496 + 0.017 + 0.05
      = 0.583
```

### 7.4 最終結果

```
┌─────────────────────────────────────────────┐
│  Input:  perm = [2, 0, 1], demand = [10, 30, 5]  │
│  Output: R_joint_hat = 0.583                │
│                                             │
│  解讀：模型預測在此排列和需求組合下，       │
│  3 組 pair 同時達標的機率約為 58.3%          │
└─────────────────────────────────────────────┘
```

> 📝 **註解**：0.583 這個值沒有經過 sigmoid，因為模型訓練時用 MSE loss，
> 目標值 R_joint ∈ [0,1] 本身就在合理範圍內，模型會隱式學到合適的輸出範圍。
> 如果預測值超出 [0,1]，在 GA 搜尋階段只需要做「排名」而非精確值，
> 所以不影響最終的最佳化效果。
